> **الهدف:** القضاء على الهلوسة، تقييد مصادر البحث بكتب التفسير واللغة المعتمدة، وأتمتة التحقق العلمي أثناء جلسات التدبر.

## 1. الملخص التنفيذي (Executive Summary)

في مشروعات تدبر القرآن وتوثيق الفوائد التفسيرية واللغوية، تُعدّ **«الدقة المطلقة والأمانة العلمية»** هي المعيار الحاكم؛ فالخطأ أو "الهلوسة" (Hallucination) في نسبة قول لمفسر، أو تخريج حديث ضعيف، أو خلط في جذر لغوي يترتب عليه خلل منهجي لا يُقبل في علوم القرآن.

محرك **Vane** (المعروف سابقاً باسم *Perplexica*) هو محرك إجابات بحثي ذكي ومفتوح المصدر (Open-Source AI Search Engine)، يُعدّ بديلاً ذاتي الاستضافة (Self-Hosted) لمنصات مثل *Perplexity AI*. يجمع Vane بين:
1. محرك بحث نقي غير متعقب عبر **SearXNG**.
2. توليف ذكي وموجّه عبر نماذج اللغة الكبيرة (محلياً عبر **Ollama** أو سحابياً عبر **Gemini / Claude**).
3. استخراج الإجابات حصراً مع **هوامش وروابط توثيقية مباشرة** للمصادر (Grounded Citation).
4. أوضاع بحث مخصصة (**Custom Focus Modes**) وتقييد البحث في نطاقات ومواقع محددة (Domain Whitelisting).
5. فهرسة وبحث في المستندات والكتب المحلية (Document Search / Local RAG).

تهدف هذه الوثيقة إلى تحليل خيارات دمج Vane ضمن بيئة عمل `quran-fagr` لرفع موثوقية جلسات التدبر إلى أعلى المعايير الممكنة.

## 2. التحليل الفني لمحرك Vane (Technical Architecture Analysis)

### أ) البنية الهندسية والمكونات:
* **واجهة المحادثة والبحث (Frontend & API):** واجهة ويب تفاعلية حديثة، بالإضافة إلى واجهات برمجية كاملة (REST & WebSocket API) تتيح الاستعلام البرمجي عبر سكربتات خارجية.
* **محرك الميتاسيرش (SearXNG Meta-Search Engine):** يستعلم من محركات متعددة دون إعلانات أو ملفات تتبع، ويمكن حصر استعلاماته في نطاقات محددة (Site-Specific Operators).
* **طبقة النماذج (Model Agnostic LLMs):**
  - **محلياً (Zero-Cost / Offline):** التكامل المباشر مع Ollama لتشغيل نماذج محلية (مثل `Qwen-2.5-14B` أو `Llama-3.1` الداعمة للعربية).
  - **سحابياً (High Reasoning):** التكامل مع Gemini Flash / Pro لتحقيق أعلى كفاءة استدلالية.
* **محرك التضمين الشعاعي (Vector Embeddings):** استخدام نماذج تضمين خفيفة ومحلية للبحث الدلالي في الوثائق والنصوص المسترجعة.

### ب) المزايا المباشرة لمشروع Quran Fagr:
| الميزة في Vane | الفائدة المباشرة لمشروعنا |
| :--- | :--- |
| **Grounded Citations (التوثيق بالهوامش)** | لا تُذكر معلومة إلا برابط واقتباس مباشر من صفحة المصدر، مما يقضي على تخيلات النماذج. |
| **Domain Whitelisting (القائمة البيضاء)** | منع النموذج من التصفح العشوائي للإنترنت (منتديات، مدونات غير موثوقة، مواقع طائفية) وحصره في بوابات التفسير واللغة المعتمدة. |
| **Focus Modes (أوضاع البحث المخصصة)** | إنشاء وضع مخصص باسم `Quranic Tafsir` بنظام توجيه (System Prompt) يفرض الأركان الأربعة لمنهجية المشروع. |
| **Local File RAG (البحث في كتبنا المحلية)** | إمكانية رفع وتغذية Vane بملفات الشاملة وكتب التفسير الرقمية المعتمدة للبحث فيها دون إنترنت. |
| **REST API** | إمكانية استدعاء Vane تلقائياً من خلال سكربتات البايثون داخل المشروع أثناء تجهيز الملاحظات. |

## 3. معالجة مشكلة الهلوسة وحصر المصادر (Limiting Sources & Eliminating Hallucinations)

### أ) مصفوفة المصادر المعتمدة المسموح بها (Whitelisted Corpus):
عند ضبط Vane لمشروع `quran-fagr`، تُحصر مصادر البحث في المواقع والبوابات الرصينة التالية:

1. **أمهات كتب التفسير والبيان القرآني:**
   - `tafsir.app` (مجمع التفاسير: الطبري، السعدي، البغوي، ابن كثير، القرطبي، ابن عاشور، التفسير الوسيط).
   - `shamela.ws` (المكتبة الشاملة للبحث النصي المحقق في أمهات كتب السلف).
   - `quran.ksu.edu.sa` (جامع المصحف الإلكتروني بجامعة الملك سعود).
2. **معاجم لسان العرب وفقه اللغة:**
   - `almaany.com` (المعجم الاشتقاقي، لسان العرب، القاموس المحيط، مقاييس اللغة).
   - `al-maktaba.org` (أصول كتب النحو، المفردات للراغب، والفروق اللغوية للعسكري).
3. **تخريج وتحقيق الأحاديث النبوية:**
   - `dorar.net` (موسوعة الدرر السنية للتأكد الحاسم من صحة الأحاديث ونفي الضعيف والموضوع).
4. **النصوص القرآنية والرسم العثماني:**
   - `quran.com` و `surah.nu`.

### ب) كيف يقضي Vane على الهلوسة عملياً؟
1. **الخطوة 1 (الاستعلام المحصور):** يبحث SearXNG فقط في النطاقات المعتمدة السابقة.
2. **الخطوة 2 (استخراج الاقتباسات):** يجلب المحرك الفقرات النصية المحققة من صفحات التفاسير.
3. **الخطوة 3 (التلخيص المشروط):** يُوجّه النموذج بـ System Prompt صارم: *«يُمنع منعاً باتاً إضافة أي معلومة غير موجودة في النصوص المقتبسة المرفقة، ويجب إسناد كل قول لمصدره ورابطه»*.
4. **الخطوة 4 (المراجعة المقارنة):** تُعرض الإجابة مع أرقام إحالات واضحة يُمكن لمحرر الجلسة النقر عليها للتأكد من نص المفسر الأصلي.

## 4. مقترح خطة العمل والدمج (Enhancement Workflow Proposals)

نوصي بتنفيذ هذا التكامل على **أربع مراحل متدرجة**:

### المرحلة 1: التشغيل المحلي وتخصيص وضع التفسير (Local Setup & Custom Focus)
* تشغيل Vane محلياً عبر Docker Compose على جهاز العمل:
  - Vane Backend + Frontend.
  - SearXNG مُعدّل بالقائمة البيضاء للمصادر الإسلامية المعتمدة.
  - الربط مع Ollama (أو مفتاح Gemini المجاني).
* إنشاء وضع تركيز مخصص: **`Focus Mode: تدبر وتفسير القرآن`**.
  - تضمين توجيه المنهجية الرباعية (الجذر اللغوي ⬅️ المعنى التركيبي ⬅️ أقوال الطبري والسعدي والطنطاوي ⬅️ اللطائف البلاغية والتدبرية).

### المرحلة 2: سكريبت التحقق السريع من التفسير (`scripts/search_tafsir.py`)
* إنشاء أداة سطر أوامر خفيفة داخل المشروع للتواصل مع محرك Vane:
  ```powershell
  python scripts/search_tafsir.py -s "الأنعام" -a 76 -q "لماذا اختار لفظ أفل دون غيره"
  ```
* يقوم السكربت بإرسال السؤال إلى Vane محلياً، وجلب الإجابة الموثقة مع نصوص المفسرين وروابط صفحاتهم، لتكون تحت يد الباحث أثناء الجلسة.

### المرحلة 3: بناء وتغذية المستودع المحلي للمراجع (Local RAG Corpus)
* تزويد مجلد خاص داخل Vane بنسخ Markdown أو نصوص رقمية من الكتب التي نعتمد عليها بشكل دائم:
  - *تفسير الطبري (جامع البيان)*.
  - *تفسير السعدي (تيسير الكريم الرحمن)*.
  - *التفسير الوسيط لمحمد سيد طنطاوي*.
  - *مفردات ألفاظ القرآن للراغب الأصفهاني*.
  - *الانتصاف من الكشاف لابن المنير السكندري*.
* عند تفعيل البحث، يُعطي Vane الأولوية القصوى للكتب المحلية قبل البحث في الويب.

### المرحلة 4: أداة التحقق التلقائي قبل النشر (`scripts/validate_sources.py`)
* خطوة تدقيق أوتوماتيكية مضافة لأدوات الجلسة؛ تفحص نصوص الاقتباسات الواردة في الملاحظات وتقارنها بالنصوص الأصلية لضمان سلامة النقل قبل اعتماد النشر عبر Git.
