# مهارة إدارة وتوثيق الملاحظات وجلسات التدبر في Quran Fagr

تُستخدم هذه المهارة لإدارة جلسات التدبر الحية، تصنيف الفوائد والأسئلة والمفردات، وتوليد ونشر الملاحظات وفق المعايير الصارمة لمشروع `quran-fagr`.

---

## 1. مسار جلسات العصف الذهني والتدبر (Live Session Workflow)

### أ) أثناء الجلسة (Interactive Phase — دون استهلاك أدوات):
- **اللغة:** المحادثة والشروحات حصراً باللغة العربية.
- **التفاعل والبحث السريع:** الإجابة عن استفسارات المستخدم، تفسير الآيات، بيان الفروق اللغوية، والبحث في المعاني المرجعية.
- **توفير الـ Tokens:** **يُمنع تشغيل أدوات الملفات أو الفحص أو git أثناء الجلسة**. يقتصر التفاعل على الردود الحوارية مع الاحتفاظ بكافة الفوائد والأسئلة في سياق المحادثة.

### ب) عند انتهاء الجلسة (Post-Session Batch Processing & Shipping):
عند إشارة المستخدم بانتهاء الجلسة («انتهت الجلسة» / «وثّق ملاحظات الجلسة»)، تُنفذ الخطوات دفعة واحدة (Batch):
1. **فرز وتصنيف المخرجات** بحسب مصفوفة التصنيف الموضحة أدناه.
2. **استخراج نصوص الآيات** بالرسم العثماني من ملف `obsidian-templates/data/quran-uthmani.json`.
3. **صياغة كتل الملاحظات** وضبط سطر الميتاداتا بتاريخ اليوم.
4. **كتابة الملاحظات** في أعلى الملفات المخصصة لها (الأحدث أولاً).
5. **تشغيل فحص الاعتماد:** `python scripts/validate_notes.py` (مرة واحدة).
6. **الدفع والنشر:** إضافة الملفات المحددة بدقة ودفعها لـ `main` لتُنشر تلقائياً للموقع عبر GitHub Actions.
7. **توليد رسالة WhatsApp (حصاد الجلسة):** صياغة النص الختامي وفق القالب المعتمد بروابط الأسئلة المباشرة لعرضه للمستخدم لنسخه ومشاركته فوراً.

## 3. صيغة كتلة الملاحظة وقواعد الميتاداتا

### أ) في تدبر الآيات (`surahs/verses/`):
```markdown
## آية 255:
> "ٱللَّهُ لَآ إِلَٰهَ إِلَّا هُوَ ٱلْحَىُّ ٱلْقَيُّومُ"

*2026-10-01 · #توحيد · [البقرة:255](../quran/002-البقرة.md)*
نص التأمل والشرح...
```

### ب) في مشاركات حلقة الفجر (`surahs/fajr/`):
```markdown
## الفرق بين المُقْسِط والقَاسِط
*2026-10-01 · #لغة · #مفردات · متعلّقة بـ [المائدة:42](../quran/005-المائدة.md)*

نص الفائدة والملاحظة...
```

### قواعد سطر الميتاداتا:
1. يبدأ وينتهي بـ `*`.
2. التاريخ بالصيغة القياسية: `YYYY-MM-DD` (يربط الملاحظة تلقائياً بالختمة الجارية في `surahs/khatmas/index.md`).
3. الفاصل حصراً: مسافة + نقطة مركزية + مسافة ` · `.
4. الوسوم متعددة الكلمات تفصل بشرطة: `#حجج-باطلة`، `#أسباب-النزول`.
5. المرجع القرآني: رابط نسبي لمجلد السور: `[البقرة:255](../quran/002-البقرة.md)`.
6. يمكن استخدام الأمر السريع لتوليد السطر:
   ```powershell
   python scripts/note.py [رقم_السورة] [رقم_الآية] [الوسوم...]
   ```

## 4. متابعة الختمات بتاريخ بدايتها (Khatmas Tracking)

- **الملف المرجعي:** `surahs/khatmas/index.md`.
- **معيار التوثيق:** تُحفظ الختمات وتُعرف بـ **تاريخ بدايتها** (`YYYY-MM-DD`).
- **الختمة الجارية:** هي الختمة التي يكون عمود الانتهاء فيها `—`.
- **ربط الملاحظات:** كل ملاحظة يُدرج فيها تاريخ اليوم `YYYY-MM-DD` تُرصد تلقائياً ضمن الختمة الجارية بناءً على تاريخ البدء.
- **بدء ختمة جديدة:**
  إذا بدأ المستخدم ختمة جديدة بتاريخ محدد:
  1. يُستبدل `—` في الختمة السابقة بتاريخ الانتهاء.
  2. يُضاف صف جديد برقم الختمة الجديد، اسمها، وتاريخ البدء الجديد، و`—` في خانة الانتهاء.

## 5. الفحص، الاعتماد، والنشر (Validation & Shipping)

تُنفذ هذه الأوامر دفعة واحدة في ختام الجلسة فقط:
```powershell
# 1. فحص سلامة الملاحظات ومطابقتها للمعايير
python scripts/validate_notes.py

# 2. تحديد الملفات المعدلة بدقة (تجنب git add -A)
git add surahs/verses/002-البقرة.md surahs/fajr/فوائد-لغوية.md

# 3. حفظ الـ Commit
git commit -m "notes: session reflections and vocab"

# 4. النشر التلقائي عبر GitHub Actions
git push origin main
```
*ملاحظة:* يمنع تشغيل `mkdocs gh-deploy` محلياً منعاً لتضارب فروع النشر.
