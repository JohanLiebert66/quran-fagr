# مهارة إدارة وتوثيق الملاحظات وجلسات التدبر في Quran Fagr

تُستخدم هذه المهارة لإدارة جلسات التدبر الحية، تصنيف الفوائد والأسئلة والمفردات، وتوليد ونشر الملاحظات وفق المعايير الصارمة لمشروع `quran-fagr`.

---

## 1. مسار جلسات العصف الذهني والتدبر (Live Session Workflow)

### أ) أثناء الجلسة (Interactive Phase — دون استهلاك أدوات):
- **اللغة:** المحادثة والشروحات حصراً باللغة العربية.
- **التفاعل والبحث السريع:** الإجابة عن استفسارات المستخدم، تفسير الآيات، بيان الفروق اللغوية، والبحث في المعاني المرجعية.
- **توفير الـ Tokens:** **يُمنع تشغيل أدوات الملفات أو الفحص أو git أثناء الجلسة**. يقتصر التفاعل على الردود الحوارية مع الاحتفاظ بكافة الفوائد والأسئلة في سياق المحادثة.

### ب) عند انتهاء الجلسة (Post-Session Batch Processing & Shipping):
عند إشارة المستخدم بانتهاء الجلسة («انتهت الجلسة» / «وثّق ملاحظات الجلسة»)، تُنفذ الخطوات دفعة واحدة (Batch):
1. **فرز وتصنيف المخرجات** بحسب مصفوفة التصنيف وبروتوكول الدمج الموضوعي (دمج أسئلة الآية/الموضوع الواحد وفصل المستقلة).
2. **استخراج نصوص الآيات** بالرسم العثماني من ملف `obsidian-templates/data/quran-uthmani.json`.
3. **صياغة كتل الملاحظات** وضبط سطر الميتاداتا بتاريخ اليوم.
4. **فحص التكرار وموضع الإضافة:**
   - **في صفحات تدبر الآيات (`surahs/verses/`):** **الترتيب رقمي تصاعدي صارم بحسب رقم الآية في المصحف**. توضع الآية في موضعها العددي الصحيح بين آيات السورة (مثلاً آية 50 قبل آية 60)، ولا توضع في أعلى الملف. وإن وُجدت مدارسة سابقة للآية يُطبّق بروتوكول «الإثراء دون التبديل».
   - **في مشاركات الفجر العامة (`surahs/fajr/`):** الترتيب زمني (الأحدث يوضع في أعلى الملف).
5. **تشغيل فحص الاعتماد:** `python scripts/validate_notes.py` (مرة واحدة).
6. **الدفع والنشر:** إضافة الملفات المحددة بدقة ودفعها لـ `main` لتُنشر تلقائياً للموقع عبر GitHub Actions.
7. **توليد رسالة WhatsApp (حصاد الجلسة):** صياغة النص الختامي وفق القالب المعتمد بروابط الأسئلة المباشرة لعرضه للمستخدم لنسخه ومشاركته فوراً.

## 3. صيغة كتلة الملاحظة وقواعد الميتاداتا

### أ) في تدبر الآيات (`surahs/verses/`):
```markdown
## آية 255:
> "ٱللَّهُ لَآ إِلَٰهَ إِلَّا هُوَ ٱلْحَىُّ ٱلْقَيُّومُ"

*2026-10-01 · #توحيد · [البقرة:255](../quran/002-البقرة.md)*
نص التأمل والشرح...
```

### ب) في مشاركات حلقة الفجر (`surahs/fajr/`):
```markdown
## الفرق بين المُقْسِط والقَاسِط
*2026-10-01 · #لغة · #مفردات · متعلّقة بـ [المائدة:42](../quran/005-المائدة.md)*

نص الفائدة والملاحظة...
```

### قواعد سطر الميتاداتا:
1. يبدأ وينتهي بـ `*`.
2. التاريخ بالصيغة القياسية: `YYYY-MM-DD` (يربط الملاحظة تلقائياً بالختمة الجارية في `surahs/khatmas/index.md`).
3. الفاصل حصراً: مسافة + نقطة مركزية + مسافة ` · `.
4. الوسوم متعددة الكلمات تفصل بشرطة: `#حجج-باطلة`، `#أسباب-النزول`.
5. المرجع القرآني: رابط نسبي لمجلد السور: `[البقرة:255](../quran/002-البقرة.md)`.
6. يمكن استخدام الأمر السريع لتوليد السطر:
   ```powershell
   python scripts/note.py [رقم_السورة] [رقم_الآية] [الوسوم...]
   ```

## 4. متابعة الختمات بتاريخ بدايتها (Khatmas Tracking)

- **الملف المرجعي:** `surahs/khatmas/index.md`.
- **معيار التوثيق:** تُحفظ الختمات وتُعرف بـ **تاريخ بدايتها** (`YYYY-MM-DD`).
- **الختمة الجارية:** هي الختمة التي يكون عمود الانتهاء فيها `—`.
- **ربط الملاحظات:** كل ملاحظة يُدرج فيها تاريخ اليوم `YYYY-MM-DD` تُرصد تلقائياً ضمن الختمة الجارية بناءً على تاريخ البدء.
- **بدء ختمة جديدة:**
  إذا بدأ المستخدم ختمة جديدة بتاريخ محدد:
  1. يُستبدل `—` في الختمة السابقة بتاريخ الانتهاء.
  2. يُضاف صف جديد برقم الختمة الجديد، اسمها، وتاريخ البدء الجديد، و`—` في خانة الانتهاء.

## 5. الفحص، الاعتماد، والنشر (Validation & Shipping)

تُنفذ هذه الأوامر دفعة واحدة في ختام الجلسة فقط:
```powershell
# 1. فحص سلامة الملاحظات ومطابقتها للمعايير
python scripts/validate_notes.py

# 2. تحديد الملفات المعدلة بدقة (تجنب git add -A)
git add surahs/verses/002-البقرة.md surahs/fajr/فوائد-لغوية.md

# 3. حفظ الـ Commit
git commit -m "notes: session reflections and vocab"

# 4. النشر التلقائي عبر GitHub Actions
git push origin main
```
*ملاحظة:* يمنع تشغيل `mkdocs gh-deploy` محلياً منعاً لتضارب فروع النشر.

## 7. التوثيق الكامل غير المختصر لسجل الأسئلة والأجوبة (Default)
- يُسجل كل سؤال وجواب في ملف `surahs/fajr/أسئلة-وأجوبة.md` بكامل تفاصيله وشروحاته وأركانه دون أي اختصار أو قص أو تلخيص مقتضب، مع بقاء تدبرات الآيات كاملة في `surahs/verses/`.
- التوثيق الكامل والمستوفي للأركان الأربعة للبيان وأقوال أئمة التفسير المعتمدين (السعدي، الطبري، والتفسير الوسيط) هو الأصل الافتراضي المعتمد للموقع دائماً.
- إن دعت الحاجة مستقبلاً إلى نسخة مختصرة من الأسئلة والأجوبة، فتُنشأ كملخص في ملف Markdown منفصل ومستقل، ولا يُستبدل به الأصل الكامل على الموقع.

## 8. بروتوكول الإثراء التراكمي دون استبدال وقواعد دمج الأسئلة (Augment, Don't Overwrite)

قاعدة عامة ملزمة وشاملة لكافة الجلسات والأسئلة والتدبرات:

### أ) قاعدة الدمج والفصل الموضوعي (Grouping vs. Separation):
1. **الدمج عند اتحاد الموضوع أو الآية:**
   إذا دار النقاش في الجلسة حول آية واحدة أو موضوع واحد عبر عدة تساؤلات واستفسارات استطرادية لتحسين الفهم (مثل: السؤال عن دلالة لفظ، ثم استيضاح إشكال، أو توفيق بين أقوال المفسرين):
   - **تُدمج كافة الأسئلة والاستفسارات المتصلة في كتلة واحدة موحدة** تحت عنوان جامع وشامل.
   - تُصاغ الإجابة كوحدة موضوعية متكاملة تتناول كافة المحاور المطروحة بتناسق تام دون تشتيتها في مداخل متفرقة.
2. **الفصل عند تباين الموضوعات والآيات:**
   إذا كانت التساؤلات تتناول آيات متباعدة أو قضايا مستقلة لا رابط مباشر بينها، يُفرد كل سؤال وإجابته بكتلة ومسار وفائدة مستقلة تماماً.

### ب) قاعدة «الإثراء دون التبديل» وتجنب التكرار (Augment, Don't Overwrite):
1. **الفحص الاستباقي قبل الإضافة:**
   عقب كل جلسة وقبل توثيق أي مسألة، يتم فحص ملف السورة المعنية `surahs/verses/NNN-اسم-السورة.md` وسجل الأسئلة للتحقق هل سبقت مدارسة الآية أو السؤال ذاته في جلسة سابقة.
2. **التكامل والتطوير (الإثراء لا الاستبدال):**
   - **يُمنع منعاً باتاً استبدال الإجابة القديمة بالجديدة أو مسح الشروحات السابقة.**
   - بدلاً من ذلك، يتم فحص الإجابتين (السابقة والجديدة)، وتُنقح الإضافة النوعية الجديدة لتُدمج وتتكامل ضمن البنية القائمة (مثل: إضافة فرع بياني جديد، أو استدراك قول مفسر آخر كالطبري أو ابن المنير، أو تحرير استشكال لم يسبق بيانه)، ليكون الأمر إضافة وتوسيعاً لا استبدالاً.
3. **تحديث سطر الميتاداتا التراكمي:**
   عند إثراء آية أو سؤال سابق بمخرجات جلسة لاحقة، يُضاف تاريخ الجلسة الجديدة بجانب التاريخ القديم ليظهر التسلسل الزمني للمدارسة وتراكم الفوائد:
   `*2026-06-15 · 2026-10-21 · #فقه · #تدبر · [الأنعام:98](../quran/006-الأنعام.md)*`


### ج) قاعدة الترتيب الرقمي الصارم للآيات داخل السورة (Numerical Ordering):
- **صفحة السورة مصحفٌ تدبّري:** داخل كل ملف في `surahs/verses/NNN-اسم-السورة.md`، يجب أن تترتّب كتل الآيات تصاعدياً بحسب رقم الآية في المصحف الشريف (مثلاً: آية 2، ثم 50، ثم 76، ثم 93، ثم 95، ثم 97، ثم 99)، بغض النظر عن تاريخ مدارسة كل آية.
- **منع التقديم والتأخير:** يمنع منعاً باتاً وضع آية ذات رقم متأخر قبل آية متقدمة (مثل وضع 60 قبل 50، أو 99 قبل 93)؛ فحتى لو تدارسنا آية 50 بعد آية 60 بشهور، تُوضع آية 50 قبل 60 في ملف السورة ليظل جدول المحتويات (TOC) وسياق القراءة متطابقاً مع ترتيب المصحف.
- **حفظ التسلسل الزمني في مواضعه:** التتابع الزمني للجلسات محفوظ بطبيعته في أسطر الميتاداتا، وفي صفحات الختمات `surahs/khatmas/`، وفي `surahs/fajr/سجل-الأسئلة.md`.
- **الفحص الآلي الإلزامي:** يقوم سكربت `python scripts/validate_notes.py` بالفحص الآلي لتتابع أرقام الآيات في كل ملف ومنع أي مخالفة للترتيب الرقمي التصاعدي.
